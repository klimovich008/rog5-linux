## Remove instrumentation and optional correction

0172 keeps diagnostic functions built in, armed by `iris_remove()` with a
copy of `markers` and capped `marker_delay_ms`. There is no retained Iris
core pointer or module callback. Every managed release and managed action
is bracketed, including allocation, PM disable, reset, clock, OPP, domain,
ICC, IRQ and mapping cleanup. `%ps` identifies the release/action. Driver-core
markers cover DMA cleanup, driver-data clearing, domain dismiss, runtime-PM
reinit, device links, klist, notifications and uevent. IOMMU markers bracket
the group mutex and ownership decrement. This operation does not detach the
SMMU streams or destroy the context bank.

0173 brackets callback and deinit steps and module-exit completion. The
load-time `probe_no_video=1` creates no V4L2 device or node after normal
resource/PM setup; it permits a never-powered remove control. NULL nodes and
an unregistered V4L2 device are safe in remove.

0174 marks each domain-list OPP token clear/link deletion/detach, virtual
runtime disable, pstate release, genpd removal, work queue and unregister.
It observes asynchronous genpd work and provider/GDSC power-off callbacks.
Virtual devices are never dereferenced after unregister. Domain/provider
lock markers print only; no sleep or busy-wait. Delays at worker entry/exit
are outside those locks. The helper additionally refuses sleep in atomic
or IRQ-disabled context. Shared MX/MMCX activity may come from other clients;
it is context, not proof of a codec hardware access. Domain diagnostics stay
armed until the next Iris probe to observe late work after module exit.

0175 keeps `remove_quiesce=0` by default. When selected on SM8350, the locked
DEINIT/unpowered/unheld/unpinned/no-openers/no-instances state skips redundant
deinit, retaining final IRQ synchronization. Runtime PM is then disabled
before mutex destruction through an Iris-owned devm action consumed once.
The default path uses the original order and PM-disable operations.
This addresses a real lifetime weakness; it is not a proven hard-hang fix.
No VIDEOCC supply hold, GDSC flag, SMMU-route or IOVA-reservation change was
justified before the failing marker is known.

0178 separately rejects core initialization with `-ENODEV` under `core->lock`
once removal starts, before the INIT fast path or any hardware/firmware work.
This closes the lifecycle gap identified in the remove analysis; normal module
ownership already prevents most such overlaps. It is not a claim about the
hard-hang cause and does not alter ordinary decoding.

## VP9: stock versus F2r

Reference root:
`~/Projects/rog-phone-linux-migration/kernel-src/msm-5.4/techpack/video/`.
Files below are relative to that root. Stock source hashes and the trace
were inspected locally; no firmware disassembly or stock runtime trace is
available. The exact validation predicate inside the OEM firmware is unknown.

| Field or setup | Stock source | F2r / Iris | Conclusion |
|---|---|---|---|
| FTB wire layout | `msm/vidc/hfi_packetization.c:create_pkt_cmd_session_ftb` | 44 bytes; w3 stream, w4 offset, w5 allocation, w6 filled, w7 tag, w8 pixel address, w9 extradata address, w10 extradata size | Layout matches; there is no buffer-type or secure-flag word in this packet. |
| Split DPB role | `msm_vidc_common.c:msm_comm_queue_dpb_only_buffers`: HAL_BUFFER_OUTPUT becomes stream 0 | Stream 0; client CAPTURE is stream 1/OUTPUT2 | Keep the stream. Routing references to stream 1 would change their role. |
| IOVA alignment | `msm_smem.c` DMA/IOMMU allocation, stock output constraints | First addresses 0xb8c00000, 0xb8800000, 0xb8400000; 4 MiB aligned; inside reserved non-secure window | Meets 4 KiB and 512-byte alignment. `pPacketbuffer` values in the firmware error match w8, not w4. |
| DPB size | `include/uapi/vidc/media/msm_media_info.h:VENUS_BUFFER_SIZE`, two-field NV12_UBWC sizing | 0x312000, 4 KiB aligned, in every rejected 1080p stream-0 FTB | k117 already matches this size; padding/count experiments do not establish a size/alignment fault. |

| Buffer-size property | Stock `vidc_hfi.h:HFI_PROPERTY_PARAM_BUFFER_SIZE_MINIMUM`; Iris `BUFFER_SIZE_ACTUAL` | Both are 0x20100c with the same type/size payload | Names differ, bytes do not. No switch added. |

0176 defaults off, load-time only, limited to OEM VP9 split decoder DPBs.
Allocation failure or an invalid extradata DMA range returns before FTB.
The single buffer stays stable across resolution changes and is freed only
inside the existing confirmed SESSION_END/PAS-shutdown guard. Held firmware
retains it, as it retains other firmware-visible allocations. Decoder CAPTURE,
H.264, HEVC, encoder and other SoCs retain their old packets.

0177 `trace_config=1` records every sent non-ETB/FTB packet (first 16 words),
without marker delay. All current gen1 setup properties fit; larger future
packets would be truncated. This preserves setup properties before a burst
of FTB traffic evicts the ring. DPB markers identify pixel and extradata pairs.
The upstream [gen1 command implementation](https://kernel.googlesource.com/pub/scm/linux/kernel/git/phy/linux-phy/+/bf4afc53b77aeaa48b5409da5c8da6bb4eff7f43/drivers/media/platform/qcom/iris/iris_hfi_gen1_command.c)
was a secondary layout cross-check; the local ASUS lahaina source is the
basis for this experiment.

## Tests and self-review

The registered Iris suite replays 0172-0178 onto pinned GPL k117 fixtures and
compiles actual patched functions against inert APIs. It checks trace scope,
delay cap/no atomic sleep, FTB stream/wire fields, switch/platform/codec/domain
gates, shared allocation reuse, allocation/window failures, confirmed-release
cleanup, remove ordering, every skip-deinit refusal condition, NULL-node control,
core-init rejection before the INIT fast path and hardware work, and exact-source
equality when the prepared source is supplied.

The encoder suite executes the actual shell script with redirected inert
sysfs and command adapters. It checks all six stages and 60 frames, timeout,
stale/missing current-stage marker, kernel warning, fatal error, wrong frame
count, open clients and rejected options. The script now inspects stage-local
kernel messages while retaining raw dmesg, stops on kernel/SMMU faults, and
accepts only reviewed command boundaries and delay 0..1000.

Self-review kept normal resource release helpers intact, checked late logging
against freed core/virtual-device lifetimes, checked action single ownership,
and rejected a superficial property rename and unsupported static DPB
registration. Patch 0179 remains available; no unrelated kernel work
was put into this branch. Host build/test evidence is recorded in the
[k120 result](../../test-results/2026-10-02-video-iris-k120-host.md).
