**2. Deferred USB/SAFE requests erase deferred DP routing.**

[combo.c:4616](<scratchpad>/fix/dp4/k/b1/drivers/phy/qualcomm/phy-qcom-qmp-combo.c:4616) overwrites `req_mode` before deciding to defer USB-only.

Sequence: applied C/four lanes → D/two lanes deferred → late UCSI USB/SAFE. The pending D request disappears, bus width returns to four, and the next first init retains C. This defeats quick-swap recovery and can permit four-lane training toward a two-lane assignment.

Preserve the pending DP request by handling deferred USB-only **before** publishing:

```diff
@@ before qmp->req_mode = new_mode
+	if (new_mode == QMPPHY_MODE_USB3_ONLY &&
+	    qmp->qmpphy_mode != QMPPHY_MODE_USB3_ONLY &&
+	    (qmp->dp_powered_on || qmp->dp_init_count))
+		return 0;
+
 	qmp->req_mode = new_mode;
```

**3. `link_info` publication still permits mixed capabilities.**
