- **P2 — A present SPI-config region can fail without failing interrupt setup.** At [patch:114](/home/deck/.local/state/rog5-prod-boot-20260923/patches/linux-7.2.7/0144-irqchip-qcom-pdc-program-the-SPI-edge-level-config-register.patch:114), failed `ioremap()` only warns; [patch:56](/home/deck/.local/state/rog5-prod-boot-20260923/patches/linux-7.2.7/0144-irqchip-qcom-pdc-program-the-SPI-edge-level-config-register.patch:56) then returns “unchanged.” The bounds failure at line 65 does likewise, silently. **Scenario:** mapping fails, or DT supplies an undersized region covering fewer than SPI 566; RT1715 IRQ setup succeeds while its stale edge bit remains, reproducing the dead ALERT interrupt. Preserve the no-op when `reg[1]` is absent, but fail probe when a present region cannot be mapped, and validate that it covers the PDC mappings. Vendor initialization treats mapping failure as fatal.

The requested correctness checks:

| Area | Assessment |
|---|---|
| Register calculation | Correct. PDC 116 maps to DT SPI 566, which GIC translates to INTID 598. Subtracting 32 selects offset `0x44`, bit 22: **`0x17c00134`**. All 168 SM8350 mappings fit; SPI 767 is accepted and 768 rejected. |
| Locking | Correct shared-word RMW protection using `pdc_lock`, a raw spinlock with IRQ saving. The lock is released before calling the GIC parent, avoiding added lock nesting. Existing per-pin PDC configuration writes remain outside it; that is pre-existing behavior. |
| Missing `reg[1]` | Retains existing behavior without accessing MMIO, as intended for the optional resource. |
| Scope | Every routed interrupt reaching `set_type` gets its bit checked and corrected. Only changed words are written; neighboring bits are preserved. This matches vendor intent. |
| Hierarchy ordering | PDC config → SPI config → parent GIC type matches vendor ordering. Falling/both edges normalize to rising; low levels normalize to high without changing the edge/level decision. Parent failure still leaves earlier hardware changes applied, following the existing non-transactional pattern. |
| Pending state | Clearing pending after successful parent configuration when **either** configuration changes is sensible. Masking covers setup, and a continuously asserted level remains eligible to become pending. No new pending-state defect identified. |

**CX-collapse retention remains unproven.** Neither this patch nor the inspected vendor driver restores these registers on resume; normal IRQ resume does not rerun `set_type`. That supports an expectation of hardware retention or firmware restoration, but the [recorded suspend tests](/home/deck/.local/state/rog5-prod-boot-20260923/test-results/2026-09-29-standby-ddr-floor.md:14) never reached CX collapse. If the bits reset there, this patch will not repair them on resume.

**A protected MMIO access could fault.** `ioremap()` does not establish write permission, and successful register reads do not prove writes are allowed. The ASUS vendor driver directly accesses the same address, providing strong board-specific support. Other Qualcomm implementations use SCM for protected SPI-config registers, so this cannot establish safety across all supported SoCs. [SCM-capable implementation](https://android.googlesource.com/kernel/common/+/e113eb454e92/drivers/irqchip/qcom-pdc.c).
