**1. `0116` — ship after fix; keep the async arm experimental.**

- **`dp_ctrl.c:432`: incomplete asynchronous implementation.** Bit 0, MISC0 bit 0, and TU `async_en` change signalling and buffering, but bit 1 still selects static M/N. Stock uses both configuration bits, synchronous MISC0, and software M/N. AMD also enables automatic M measurement; its programmed M/N are initial values. In asynchronous mode, the sink uses M/N as clock-recovery hints and aligns regenerated timing with BE reception. Static M/N may therefore produce a picture, but this does not establish compliant asynchronous transmission. The source must measure M and transmit its updates. [VESA DP specification, §2.2.3](https://www.pedestrian.com.cn/_downloads/892024c3033a4fa8c97b2022ac08550a/DP_V1.4.pdf).
- **`dp_panel.c:303`: floor overrides ceilings.** An 18-bpp EDID or `dp_max_bpc=6` becomes 24 bpp. Reject that conflict instead. The actual TMDS downstream limits returned by 0093 are ≥8 bpc, so its ordinary 8-bpc case remains compatible. With 0110, two-lane HBR provides 4.32 Gb/s; 1080p60 uses 3.564 Gb/s at 24 bpp and fits.
- **`dp_link.c:76` (r98): D0 falsely succeeds after all writes fail.** This existing helper bug makes the new experiment’s `rc=0` misleading.
- **Clock/AUX placement passes.** Enable holds a runtime-PM reference; AUX transfers also acquire one. Unplug disables transfers, causing rejection before AUX MMIO. The new register reads execute after clocks are enabled; the retrain helper does not disable them. I found no new instance of 0091’s unclocked link-register access.

**2. Phosh `0002` — ship after ordering fix. Switcher diff — don’t ship as a “no bypass” guarantee.**

Both source claims hold:

- `src/screen-saver-manager.c:301,815`: `GetActive` returns monitor blanking state; a lit lock screen returns false.
- `src/main.c:157` locks before the main loop. Shell setup later creates the screensaver manager, whose logind initialization is asynchronous. The startup lock is never published by unpatched source. **The three particular boots cannot be established from source alone.**

The added publication is correctly placed after proxy creation and signal registration. Failed/cancelled construction returns before it; the manager NULL guard is appropriate. Repeated publication is idempotent.

**Switcher bugs, `scripts/device/rog5-desktop-mode:35,42,52`:**

- Global `pgrep` and `phone_session()` select identities independently. A locked session A followed by session B’s default `no` authorizes B without observing B locked. I reproduced this using the supplied functions.
- PID alone misses PID reuse.
- Even identity-bound polling has a check/start race and asynchronous hint propagation: Phosh can lock after the last `no` observation.

A fuller implementation should bind PID/start time to its session through [`GetSessionByPID`](https://github.com/systemd/systemd/blob/main/man/org.freedesktop.login1.xml), and coordinate the handoff with Phosh’s actual lock state.
