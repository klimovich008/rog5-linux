A stopped underrun counter does **not** establish a healthy pipeline. Check whether VSYNC, INTF line/frame counters and CTL flush completion continue. The counter can stop because timing or interrupt handling has stopped, while the last underflow-colour output remains visible. The inspected code provides no evidence for a distinct “blue latch” register that can simply be cleared.

Stock does not automatically reset on every underrun either: its underrun handler logs/dumps. Its useful recovery difference is that **a CTL-reset timeout sets `SDE_ENC_ERR_NEEDS_HW_RESET`**, and its temporary VSYNC unregister is paired with re-registration. [Stock video recovery:957](/home/deck/Projects/rog-phone-linux-migration/kernel-src/msm-5.4/techpack/display/msm/sde/sde_encoder_phys_vid.c:957), [stock underrun handler:3128](/home/deck/Projects/rog-phone-linux-migration/kernel-src/msm-5.4/techpack/display/msm/sde/sde_encoder.c:3128).

This proposal covers initial attachment with a settled assignment. Live reassignment also needs attention: QMP presently returns success while declining a mode switch if DP is powered. [QMP mux:4474](/home/deck/.local/state/rog5-kernel-7.2.7-build-r94/source/drivers/phy/qualcomm/phy-qcom-qmp-combo.c:4474). A C↔D reconfiguration must quiesce the stream, apply the switch, refresh capabilities and retrain; reporting a deferred switch as successful is insufficient.

To observe firmware’s choice, capture the GLINK notification before conversion:

- SC8280-format notification: `mux_ctrl`, orientation, raw `pin_assignment`, HPD and HPD IRQ.
- Raw assignments **3=C, 4=D, 5=E**; the driver subtracts `DPAM_HPD_A` to produce the zero-based modal index. [pmic_glink_altmode.c:487](/home/deck/.local/state/rog5-kernel-7.2.7-build-r94/source/drivers/soc/qcom/pmic_glink_altmode.c:487).
- Compare that with QMP’s accepted mode and the final DPCD lane count. Receiver capability alone is insufficient.

The inspected stock GLINK protocol exposes PAN enable and acknowledgment, **no documented “USB3 not needed” or pin-selection command**. Stock’s `force_multi_func` changes local interpretation; it is not evidence of a firmware negotiation request. Stock follows C/E by releasing USB SS lanes and configuring four-lane DP. [Stock dp_altmode.c:133](/home/deck/Projects/rog-phone-linux-migration/kernel-src/msm-5.4/techpack/display/msm/dp/dp_altmode.c:133).

Host-driven configuration is possible through UCSI **only if firmware advertises alternate-mode override**: the driver sends `SET_NEW_CAM` with the DP configuration. Otherwise later changes return `-EOPNOTSUPP`. [UCSI displayport.c:186](/home/deck/.local/state/rog5-kernel-7.2.7-build-r94/source/drivers/usb/typec/ucsi/displayport.c:186). The `displayport/pin_assignment` sysfs control is therefore conditional, and its synthesized state should not replace the raw GLINK observation.

The stock source establishes four-lane support on this phone; it does **not** establish that Android negotiated four lanes with this particular monitor. That requires a stock notification or PD capture.

**Pass/fail test:** first keep HBR2 and test four lanes independently of HBR3. Use native DP, both orientations, and record firmware assignment → QMP mode → negotiated lanes. Then test HBR3 separately.

- C/E passes when QMP enters DP-only, four lanes train, and moving content remains clean.
- D passes when the PHY remains USB3+DP and MSM uses at most two lanes—even with a four-lane DPCD receiver.
- The existing HDMI hub must retain its 0110 HBR cap and working USB2 devices.
- HBR3 passes only with actual 810000-kHz training, clean lane status/error counters and repeated working video. Source support alone is not a pass.

**3. USB full-speed `-71` after role switching**

First, the effective side-port configuration is **`dr_mode="otg"` with a peripheral default**, not literal peripheral-only mode. [OTG overlay:68](/home/deck/.local/state/rog5-prod-boot-20260923/dts/qcom/sm8350-asus-rog-phone5-usb-otg-side.dtso:68). Literal peripheral mode makes `dwc3_set_mode()` return without switching.
