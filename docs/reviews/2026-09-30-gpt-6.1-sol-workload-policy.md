1. **[P1] The persistent-state gate is not enforced on every path.** [rog5-usb-storage:132](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:132) checks only the P2 PASS record. [rog5-usb-storage@.service:14](/home/deck/.local/state/rog5-prod-boot-20260923/configs/systemd/rog5-usb-storage@.service:14) merely orders after persistent-state; it does not require that service to succeed or remain active. Direct script invocation can mount while persistent-state is starting. Restarting persistent-state also leaves USB storage mounted, causing its block-mount validation to reject startup. Require both gates, validate persistent-state’s current-boot record, and couple their stop/restart lifecycle. Normal coldplug ordering appears sound; [systemd documents ordering and requirements separately](https://raw.githubusercontent.com/systemd/systemd/v257/man/systemd.unit.xml).

2. **[P1] Absent-disk writes remain possible for root services.** [rog5-usb-storage:161](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:161) leaves the underlying directory root-owned **0755**, permitting root writes. `/srv` and `/mnt` targets remain after unmount; root can also recreate removed `/run/media` targets. This falls short of “never let writes land in an empty mountpoint.” Consumers need dependencies on the actual mount, plus an underlying directory that rejects writes when uncovered.

3. **[P1] Concurrent matching disks can mount over each other.** [rog5-usb-storage:153](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:153) checks mountpoint availability before fsck, without locking or rechecking before `mount`. Two devices labelled `ROG5-USB` start separate instances and can both pass while one is checking its filesystem, then stack mounts at the same target. Unmounting can subsequently detach the wrong volume. Serialize by target and reject ambiguous matches.

4. **[P1] GNOME suspend inhibitors can be ignored.** [rog5-sleep-policy:192](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-sleep-policy:192) accepts only mode `block`. [GNOME 50 uses `block-weak` for session suspend inhibitors](https://raw.githubusercontent.com/GNOME/gnome-session/50.0/gnome-session/gsm-systemd.c). The parser reproduction returned no blocker for that reply, allowing the daemon’s unconditional suspend despite the application’s inhibition. Honour `block-weak` for this automatic policy too; the phone’s installed GNOME version was not verified.

5. **[P1] Mount-record failures silently lose cleanup ownership.** [rog5-usb-storage:175](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:175) ignores failures creating the state directory and writing its record. I reproduced exit **0** and “mounted” after both failed. `umount NAME` then reports “nothing mounted” and leaves the filesystem attached. Prepare recording before mounting and roll back if publication fails.

6. **[P1] Symlinked parent directories defeat unmount tracking.** [rog5-usb-storage:155](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:155) rejects only a symlink at the final component. With `/srv/link → /srv/real`, the recorded target is `/srv/link/disk`, while mountinfo contains `/srv/real/disk`. [The cleanup comparison:187](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-usb-storage:187) skips unmounting, deletes the record and reports success. Reproduced with mocked mountinfo. Reject symlink ancestors or consistently validate and record the canonical target.

7. **[P1] Stale charging behaviour plus a host partner can prevent suspend indefinitely.** [rog5-sleep-policy:150](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-sleep-policy:150) treats any non-auto behaviour and **any** Type-C partner as external power. A bottom-port disk is a partner even when the phone supplies its power. With stale `force-discharge` and charge-policy stopped, all supplies can report offline while this returns `usb-power-suspended` forever. Reproduced in memory. Require evidence that the partner supplies power.

8. **[P1] Inhibitor-query failure permits forced suspend.** [rog5-sleep-policy:171](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/rog5-sleep-policy:171) makes a failed D-Bus query indistinguishable from no blocker; [the test:52](/home/deck/.local/state/rog5-prod-boot-20260923/scripts/device/test-rog5-sleep-policy.sh:52) explicitly expects `sleep-eligible`. A transient query failure at the idle deadline can therefore bypass a still-held workload inhibitor. Distinguish errors and defer suspension until a successful query.

9. **[P2] Change events do not reliably start or retry mounting.** [94-rog5-usb-storage.rules:11](/home/deck/.local/state/rog5-prod-boot-20260923/configs/udev/94-rog5-usb-storage.rules:11) adds `SYSTEMD_WANTS` on changes, but [systemd acts on these dependencies only when a device first becomes active](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.device.xml). A filesystem becoming identifiable later, or configuration added for an attached disk, will not automatically start mounting. Provide an explicit reconciliation/retry path.
