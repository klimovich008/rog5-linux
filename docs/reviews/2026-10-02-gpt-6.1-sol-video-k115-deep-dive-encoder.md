**The actual k115 property stream**

With ordinary H.264 controls, each port’s configuration executes:

```text
FRAME_RATE                       CAPTURE call only
UNCOMPRESSED_PLANE_ACTUAL_INFO    INPUT: two image planes
FRAME_SIZE                       INPUT, OUTPUT
UNCOMPRESSED_FORMAT_SELECT        INPUT: NV12
BUFFER_COUNT_ACTUAL              INPUT: 32/32; OUTPUT: 32/32

PROFILE_LEVEL_CURRENT            four times
WORK_MODE                        2
SYNC_FRAME_SEQUENCE_HEADER       1 by default
TARGET_BITRATE                   requested bitrate, layer 0
RATE_CONTROL                     VBR_CFR
INTRA_PERIOD                     29 P / 0 B by default
H264_ENTROPY_CONTROL              CAVLC by default
SESSION_QP_RANGE                  four times
```

The order comes from the configuration array followed by numeric capability-ID traversal, not from the textual order of the capability table. Both port handlers call it. Disabled IR, LTR, hierarchy and unrequested layer bitrates generally return without sending, using `-EINVAL` as “not applicable.” [`K/iris_hfi_gen1.c:391–397`; `K/iris_hfi_gen1_command.c:1170–1208`; `K/iris_platform_common.h:105–185`; `K/iris_ctrls.c:1487–1497`; `K/iris_ctrls.c:655–656`; `K/iris_ctrls.c:1123–1124`; `K/iris_ctrls.c:1177–1185`; `K/iris_ctrls.c:1387–1388`]

Thus raw-first STREAMON can produce:

```text
properties without FRAME_RATE
SET_BUFFERS(PERSIST, SCRATCH, SCRATCH1, SCRATCH2)
LOAD → LOAD_DONE → START → START_DONE
CAPTURE properties, including FRAME_RATE
deferred ETBs → deferred FTBs
```

This is a source-derived possible sequence, not boot D’s observed sequence. [`K/iris_venc.c:464–519`; `K/iris_hfi_gen1_command.c:230–258`; `K/iris_hfi_gen1_command.c:1101–1107`; `K/iris_vb2.c:204–209`]

**Definite host packet defects**

The property header occupies 16 bytes; adding one property ID makes the fixed part 20 bytes. Profile/level supplies `payload_size=4`, so allocation requests 24 bytes. The packetizer writes an eight-byte profile/level structure and declares/submits 28 bytes. This exceeds the requested allocation by four bytes. A slab may round that allocation upward, so this is not proof of adjacent-object corruption on D; it is still a real allocation-boundary violation. [`K/iris_hfi_gen1_defines.h:203–207`; `K/iris_hfi_gen1_defines.h:337–340`; `K/iris_ctrls.c:602`; `K/iris_hfi_gen1_command.c:676–689`; `K/iris_hfi_gen1_command.c:852–865`]

Entropy has the same requested-versus-wire-size mismatch. CAVLC submits the extra word outside the requested allocation; CABAC additionally writes `cabac_model` there. Fixing only profile/level leaves this second defect. [`K/iris_ctrls.c:809–826`; `K/iris_hfi_gen1_defines.h:454–457`; `K/iris_hfi_gen1_command.c:727–734`; `K/iris_hfi_gen1_command.c:852–865`]

Profile/level translation is independently wrong: V4L2 enums are not generally HFI enums. High happens to coincide; zero profile is replaced with H.264 High, and zero level with 1, rather than translating codec-specific values. This also makes the generic fallback inappropriate for HEVC. [`S/msm_vidc_common.c:360–384`; `S/vidc_hfi_helper.h:80–108`; `K/iris_ctrls.c:590–595`; `K/iris_hfi_gen1_command.c:679–687`]

Error handling compounds these problems: capability setter errors are discarded, and unsupported gen1 properties are converted into success. The proposed 0165 improves some error handling but explicitly ignores every `-EINVAL`; that would continue hiding a genuinely malformed/rejected setting. Normal inapplicable cases need to return zero before making all real errors fatal to startup. [`K/iris_ctrls.c:1496–1497`; `K/iris_hfi_gen1_command.c:857–865`; `W/patches/linux-7.2.7/0165-media-iris-ROG5-encoder-bring-up-guards-markers-DMA-window-errors-start-gating.patch:199–214`]

**Instrumentation that survives the failure**

The current trace is insufficient: it stores 64 entries with 14 words per packet, in ordinary RAM, and records transmission after queue write but before the doorbell. Encoder ETB needs 16 words; QP-range needs 21. More importantly, a trace dumped only after a detected fatal response cannot help when the host freezes first. [`K/iris_core.h:29–30`; `K/iris_core.c:17–25`; `K/iris_hfi_queue.c:129–131`; `K/iris_hfi_gen1_defines.h:459–470`; `S/hfi_packetization.c:506–539`]

Use three complementary channels:

- **Persistent records:** retain the existing 4 MiB ramoops layout at `0x9b800000`: 1 MiB dump, 3 MiB console. The ASUS wrapper boots first and replaces the console zone; a panic dump survives with the matching layout. Therefore, capture the old console from the wrapper’s first userspace before kexec, or use a separate explicitly reserved persistent breadcrumb region whose ownership and reset survival are verified. Do not silently carve a new journal into the existing ramoops layout. [`D/journal-trial-boot.txt:177–180`; `W/scripts/device/compose-production-dtb.sh:65–84`]
- **Direct breadcrumbs:** add a preallocated, bounded journal writer independent of printk, allocation and driver mutexes. Record operation PRE and POST, sequence, CPU, session/generation, arguments, return value and packet length; commit validity last after appropriate memory/cache ordering. Map it early enough to record probe/open/resume. Its persistence must be tested through the actual watchdog→wrapper→trial boot chain. This is a proposed design; the current driver trace is ordinary-memory `memcpy`. [`K/iris_core.c:17–25`; `W/scripts/device/compose-production-dtb.sh:75–79`]
- **External capture:** continuously stream kernel messages to a host over USB, and preferably capture the physical UART already named by `console=ttyMSM0,115200n8`. USB requires functioning CPU/USB scheduling and cannot guarantee delivery of the last message. Netconsole likewise needs a demonstrated device/netpoll path; enabling it is not proof that USB networking will flush during a hang. [`D/journal-trial-boot.txt:75`; `T/net/core/netpoll.c:165–193`; `T/drivers/net/usb/usbnet.c` netdev operations]

The ramoops console backend writes when its console callback runs; adding `dev_warn()` does not establish that the message has reached persistent storage or an external receiver before the next dangerous MMIO. The direct journal must be the ordering evidence. [`T/fs/pstore/platform.c:394–406`; `T/fs/pstore/ram.c:318–321`; `W/patches/linux-7.2.7/0165-media-iris-ROG5-encoder-bring-up-guards-markers-DMA-window-errors-start-gating.patch:155–168`]

Record these boundaries, without adding speculative register reads:

```text
OPEN enter/exit
each ioctl enter/exit + complete returned format/control/count
PM get before/after; instance/core lock before/acquired
each existing SCM/clock/ICC/domain/reset operation before/after
SESSION_INIT: build → queue copy → index publish → doorbell → response
```
