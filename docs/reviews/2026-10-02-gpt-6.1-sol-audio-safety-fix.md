# GPT-6.1-Sol review: audio safety fixes (2026-10-02)

Review of branch agent/fix-audio-261002 (fixes for audits 02/08/09/11 of ~/.local/state/rog5-sol-audit-20261002). Round 1 and 2 findings were fixed; round 3's one finding (a missed DSP resume after the forced mux change) was fixed after it, with a test.

## Round 1

The diff fixes the original control ordering and udev match, but **speaker safety still has gaps**. I found seven issues; the first four are high severity.

1. **High — attenuation read-back can confirm a failed hardware write.** [production-audio-route:612](initramfs/production-audio-route:612)  
   `set_confirmed()` ignores the write result. In k113, CS35L45 volume reads use regcache; regmap updates that cache **before** attempting the I²C write. A failed `409 → 361` write can therefore read back `361` while hardware remains at `409`. Subsequent retries can also skip the hardware write because the cache already matches. The route then selects direct playback and stops protection.  
   **Fix:** require a driver operation that forces attenuation and verifies hardware, with a fault latch until recovery succeeds. Merely checking the write result before the cached read is insufficient across retries. Add a fake with separate cache and hardware values.

2. **High — successful DACPCM control writes do not establish the protected hardware path.** [production-audio-route:647](initramfs/production-audio-route:647)  
   k113’s DAPM mux setter returns the logical control change; hardware update errors are logged without being propagated. During a running stream, selecting `DSP_TX1` can appear successful while hardware remains on `ASP_RX1`; the next write raises volume to `409`. An in-memory false-success reproduction returned success with **409/direct/amplifier-on**.  
   **Fix:** verify the actual mux before granting `409`, preferably through a driver safety gate that rejects volume elevation after failed routing. Ordinary ALSA read-back can also be cached.

3. **High — failed muting still enables shared playback.** [production-audio-route:692](initramfs/production-audio-route:692), [mute_amp:622](initramfs/production-audio-route:622)  
   If attenuation, amplifier-disable and DACPCM-zero writes all fail, `mute_amp()` reports “amplifier muted” and `route_card()` continues through shared controls and mixer enable. I reproduced the final state **RCV=409, ASP_RX1, AMP=1, playback mixer=1**.  
   **Fix:** return whether isolation was actually confirmed. If an unsafe amplifier cannot be isolated, abort before shared route changes or mixer enable; report mute failure accurately. Add this case to the card-level tests.

4. **High — failed quarantine leaves unsafe restoration authorized.** [production-audio-route:187](initramfs/production-audio-route:187), [89-rog5-alsa-state.rules:23](configs/udev/89-rog5-alsa-state.rules:23)  
   When rewriting **and** renaming fail—for example, on a read-only filesystem—the sanitizer logs the failure and returns zero. The readable unsafe file remains available to both restore entrypoints. I reproduced this with both operations returning `EROFS`.  
   **Fix:** explicitly gate udev restoration and `alsa-restore.service` on successful sanitization, or make ROG5 restoration use a guarded safe file. A nonzero `IMPORT` result alone would not suppress subsequent restore rules. Test failure of both rewrite and quarantine.

5. **Medium — valid ALSA syntax bypasses the sanitizer.** [production-audio-route:170](initramfs/production-audio-route:170), [sanitize_alsa_state:233](initramfs/production-audio-route:233)  
   Lines such as `value 409 # saved gain` and `value true # enabled` do not match `STATE_VALUE`. Their braces balance, so the file passes unchanged. Host libasound accepted this syntax; the sanitizer returned success without rewriting or quarantining it.  
   **Fix:** parse the ALSA configuration structurally, or reject every unrecognized representation of a safety-sensitive control. Test inline comments, compound values, quoted card identifiers and compact formatting.

6. **Medium — enumeration lookup still ignores `CTL_INFO` errors.** [rog5-alsa-probe.c:387](tools/alsa_probe/rog5-alsa-probe.c:387)  
   Both calls inside `enum_name()` remain unchecked. If the item-specific query fails, the name from the preceding default-item query survives. During `set … Zero`, that can associate “Zero” with a different index and write the wrong selection. `get` can likewise report success with an incorrect name.  
   **Fix:** propagate every enumeration-query error before comparing, printing or writing. Inject failures at individual enumeration queries; the current test only fails all information queries.

7. **Medium — decimal overflow defeats range validation.** [rog5-alsa-probe.c:180](tools/alsa_probe/rog5-alsa-probe.c:180), [cmd_set:490](tools/alsa_probe/rog5-alsa-probe.c:490)  
   `parse()` performs unchecked signed multiplication and addition. Oversized input invokes undefined behavior before validation; `18446744073709552025`, for example, corresponds to `409` after 64-bit wrapping.  
   **Fix:** use overflow-checked parsing and test oversized positive/negative values and signed-long boundaries under UBSan.

**What is fine:** removing `KERNELS!="card*"` agrees with the supplied k113 hierarchy. Root-copy installation and preference are correct. With successful hardware operations, the attenuation → shared route → per-amp path/enable → playback ordering is sound, and the normal protected path retains its calibration/state/error checks. The type/count guard fixes the original C buffer overflow.

The retained rootfs’s udev unit has no `ProtectSystem` restriction blocking `/var/lib/alsa` writes, consistent with the [upstream unit](https://github.com/systemd/systemd/blob/main/units/systemd-udevd.service.in). Normal single-card event ordering places sanitization before restoration. The early `rog5-audio.service` route can still overlap restoration; its flock only serializes route instances. A running stream alone does not violate the limit when hardware attenuation really succeeds.

Five udev-model tests, AArch64 syntax checking and `git diff --check` passed. Full test runs could not create temporary directories under this session’s read-only sandbox. No files were modified.
## Round 2

Two findings remain.

1. **High — a no-op mux retry can falsely confirm hardware routing.** [production-audio-route:668](initramfs/production-audio-route:668)  
   A failed DAPM register write leaves both the logical mux and regcache at `DSP_TX1`, while hardware remains `ASP_RX1`. Repeating the selection performs no hardware write and emits no new error, so `set_mux()` returns success. I reproduced **409/direct/amplifier-on** on a route rerun after interrupting the first failed attempt before fallback. Repeated `Zero` selections have the same confirmation gap.

   **Fix:** force a hardware routing update or retain a fault until verified recovery. At confirmed attenuation, selecting `Zero` then `DSP_TX1` can force the protected-path transition. The [DAPM failure test:736](scripts/device/test-production-audio-route.py:736) needs separate logical, cache and hardware state, plus a no-op retry case.

2. **Medium — valid ALSA syntax still bypasses sanitization.** [production-audio-route:221](initramfs/production-audio-route:221), [force_value:181](initramfs/production-audio-route:181)  
   Host libasound accepts `name 'RCV Digital PCM Volum\e'` as `RCV Digital PCM Volume`; the sanitizer treats it as unrelated and leaves `409` unchanged. Likewise, a normal volume block containing these lines passes unchanged:

   ```text
   value 361
   'value' 409
   ```

   Libasound resolves the resulting value to **409**. Both reproductions returned success without rewriting or quarantining.

   **Fix:** enforce the accepted syntax throughout each control block, including names and keys, or parse ALSA configuration structurally. Add regressions validated against libasound.

## Round 3

Both round-2 findings are fixed. One new regression remains.

**Medium — forced mux transitions can leave playback silent while reporting success.** [production-audio-route:771](initramfs/production-audio-route:771), [error filter:723](initramfs/production-audio-route:723)

Rerunning during healthy protected playback now forces `DSP_TX1 → Zero → DSP_TX1`, triggering DSP pause/resume. If RESUME fails, the kernel logs `ASoC: POST_PMU: RCV DSP1 event failed: -5`; `set_mux()` only checks DACPCM errors and misses it. I reproduced a successful route return with volume **409** and the DSP still paused (**CSPL_STATE 2**), leaving silence until stream closure permits recovery. Previously, that healthy rerun required no transition.

**Fix:** reject amplifier DSP event and mailbox failures occurring after the mux marker, keeping attenuation and taking the existing fallback. Add an active-playback rerun regression with failed RESUME.

The seven focused routing regressions and five udev tests passed; AArch64 syntax checking and `git diff --check` passed. Representative libasound-generated [alsactl store layouts](https://github.com/alsa-project/alsa-utils/blob/master/alsactl/state.c) were accepted, preserving mic values. Both sanitizer bypass examples were quarantined. No files were modified.
