## Answer

1. **High — agree that unlocking needs the GDM daemon; correct the fallback claim.** Unlock uses `UNLOCK_ONLY`, which sets `reauthenticationOnly=true`; `get_user_verifier()` fallback is therefore **disabled for unlocking**. Without GDM, authentication fails. GDM does support unmanaged sessions: it validates the caller’s logind session, opens a temporary reauthentication channel, and unlocks that session on success. Evidence: `gnome-shell-50.5/js/gdm/authPrompt.js:162`, `js/gdm/util.js:511–527`; `gdm-50.3/daemon/gdm-manager.c:1090–1147,945–949`.

2. **Medium — daemon-only operation is technically plausible, but stock GDM provides no simple authentication-only mode.** GDM unconditionally starts its local display factory; its command-line options have no greeter-disable switch. A custom systemd session plus GDM would need additional display/VT coordination or a GDM patch. More seriously, a unit like `rog5-phosh` bypasses initial authentication, and GNOME does not inherently start locked. **Agree: GDM greeter without autologin is the better production choice.** Test touch-only greeter login separately. Evidence: `gdm-50.3/daemon/main.c:221–226`, `daemon/gdm-manager.c:2370`; [rog5-phosh.service:1](configs/systemd/rog5-phosh.service:1).

3. **High — the claimed normal suspend exception is incorrect; the wake-display conflict remains.** `PrepareForSleep(true)` explicitly enters `suspend-forced`, and `_doSystemAction()` permits upgrading `blank`/`idle-blank` to that action. Normal policy suspend therefore should not reach resume still in `blank`. The exception requires an interrupted/failed preparation or another abnormal path; “undefined state” is also overstated. **Agree:** no-action resume turns the screen on. Successful `suspend-forced` resume also normally lights it, unless proximity reports a pocket. Evidence: `pm50.js:451–478,250–300,381,498–503,685–694,870–914`.

4. **Medium — prefer retaining the phone policy and adapting wake handling.** Preserve its external-power, remote-client, audio, inhibitor and repeated-suspend behavior; patch the shell to retain blanking after policy wakes and distinguish explicit user wake. Keep lock-before-suspend and delay-inhibitor handling intact. Merely suppressing the exception is insufficient. Shell-owned suspend plus an inhibitor provider would require redesigning those behaviors and the permanent server inhibitor. The replay concern is weak: the policy already waits one second, then another second during uinput creation, exceeding the shell’s 500 ms suppression window. Evidence: [sleep-policy:25](scripts/device/rog5-sleep-policy:25), `:302,316–320,374–377`; `pm50.js:399–434,493–495`.

5. **Medium — correct the scale calculation; agree that phone classification works.** Exact divisibility is required, **but denominators are limited to four**, scales to 1–4, and upstream logical area to ≥360,000 pixels. `72/29` is unsupported. The nearest supported scale to 2.5 is **8/3**, yielding **405×918**; area 371,790 passes. Upstream 3× fails the area restriction; mobile lowers it to 560×320. `_checkIsPhone()` does divide dimensions by St’s scale factor, but logical layout sets that factor to **1**, so there is no additional reduction. Evidence: `mutter-50.5/src/backends/meta-monitor.c:33–36,2438–2442,2506–2528`; `meta-settings.c:110`; `layout50.js:1251–1256`. The later staged plan already uses the correct 8/3.

6. **High — the selector does not yet establish “never lose a working phone UI.”** A logind greeter/user session can exist while the panel is black, Shell is hung, or input/authentication is unusable; failures also need not generate core dumps. Require bounded readiness checks and an independent root watchdog armed **before** stopping Phosh. Enforce mutual exclusion and mode gates across GDM, both existing compositor units, and switcher/manual starts; current units only exclude Phosh versus desktop GNOME. Rehearse termination, DRM release and successful locked Phosh recovery. Evidence: [investigation:388](docs/reviews/2026-10-01-gnome-mobile-investigation.md:388), [rog5-gnome.service:14](configs/systemd/rog5-gnome.service:14), [polkit rule:8](configs/polkit/60-rog5-desktop-mode.rules:8).

7. **High — expand lock testing beyond rendering, PIN success and `LockedHint`.** Add GDM/PAM unavailable or restarted, rapid lock/unlock/suspend/hotplug, cancelled and stale authentication, keyboard/gesture escape attempts, notification markup, emergency-call overlays, and verification that neither output exposes application frames or accepts application input while locked. Test short/long PINs and account-lockout recovery without endangering the only usable account. Headless rendering and one source review cannot establish these properties. Evidence: [investigation:418](docs/reviews/2026-10-01-gnome-mobile-investigation.md:418); `ud50.js:502–504,531–543`; `pm50.js:879–895`.

8. **Medium — agree with most stack changes, but strengthen isolation.** Cache a complete compatible rollback package set and test it; retaining Phosh does not isolate it from replaced Mutter/Shell, shared settings or user services. A dconf file named `01-rog5-gnome-mobile` is not session-scoped. Prove gsd-power disabling and restoration across both session types. Add the fork’s `org.gnome.Shell.SensorDaemon` activation/sensor behavior and separate GDM greeter display configuration to the table. **Agree:** wayvnc is incompatible; RDP needs its own acceptance test. Evidence: [investigation:329](docs/reviews/2026-10-01-gnome-mobile-investigation.md:329), `:363–371`; `pm50.js:119–131`; [wayvnc unit:11](configs/systemd-user/rog5-wayvnc-phone.service:11).

9. **Low — agree with “not yet” and Phosh docked mode first.** Matching Arch/mobile versions reduce integration work, but “51.x branch exists” should trigger evaluation, not production acceptance; security fixes and the above gates still matter. The predicted upgrade timing and effort are estimates. A supervised Phosh trial with the switcher in `manual` mode directly tests preserving applications, while exercising the repaired hotplug path. Evidence: [investigation:14](docs/reviews/2026-10-01-gnome-mobile-investigation.md:14), `:444–448`; [Phosh README:125](packages/phosh/README.md:125).
