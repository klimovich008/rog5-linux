# ROG5 audio: stock (msm-5.4 techpack) vs ours (7.2.7 r42)

Phone was unreachable (both addresses timed out), so everything below is from source, the stock vendor image (`~/.local/state/rog5-stock-payload-20260927/parts/vendor.img`, read with debugfs) and our repo. Stock ASUS configs and CS35L45 firmware were copied to the scratchpad `kernel-compare/audio/` (mixer_paths_ZS673KS.xml, audio_platform_info_ZS673KS.xml, cs35l45-*.wmfw/.bin/.txt).

## Stock audio topology (ZS673KS)
The ROG5 does **not** use WCD938x/WSA883x/SoundWire (all `status = "disabled"`, `ZS673KS-EVB-overlay.dts:1285-1345`, `qcom,wcd-disabled = <1>` :1349). The real hardware:
- **2x CS35L45** on QUP SE17 I2C (RCV 0x30, SPK 0x31; EVB:1490-1570) on **SENARY MI2S** (LPI GPIO10-13), 48 kHz **S24_LE** stereo, LPASS master (`lahaina.c:488,497`; `msm_dailink.h:1010-1033`), HALO DSP firmware `cs35l45-{rcv,spk}-dsp1-spk-prot.{wmfw,bin}` + `-cali` + fast-switch tunings `cs35l45-{rcv,spk}-{music,voice,outdoor}.txt` (all in `/vendor/firmware`).
- **ESS ES928x (ES9280AC) 3.5 mm DAC/codec** at I2C 0x49 on the same SE17 bus (EVB:1567-1590): reset TLMM88, IRQ TLMM14, 3.3 V enable TLMM124, 1.8 V enable PM8350B GPIO5, 49.152 MHz XOSC, ESS is I2S master; playback on PRI MI2S RX (TLMM 125/126/128, `lahaina-pinctrl.dtsi:2474-2536`), headset mic on QUAT MI2S TX (LPI GPIO0-2, `lahaina-lpi.dtsi:17-79`); `qcom,msm-mi2s-master = <0>,<1>,<1>,<0>,<1>,<1>` (EVB:1348). Jack/button/impedance detection in the codec driver (`es928x.c:1005-1330`), jack registered by `msm_audrx_ess_init` (`lahaina.c:5798-5835`). Firmware `ES928X.ROM`/`ES928XA.ROM`.
- **4 digital mics** on the Bolero (LPASS codec v2.0, `bolero-cdc.h:14`) TX macro via the LPI pins gpio6-9 (`lahaina-lpi.dtsi:1518-1610`, `cdc_dmic45` disabled because gpio12/13 are the i2s2 data pins), mic bias from **L2C** (EVB:1277), captured over `TX_CDC_DMA_TX_3` (`mixer_paths_ZS673KS.xml:2637-2661`: dmic1=DMIC0 handset, dmic2=DMIC2 speaker-mic, dmic3=DMIC1, dmic4=DMIC3).
- FSA4480 USB-C analog switch disabled (EVB:154-157); swr haptics disabled; BT audio via SLIMBUS 7 to WCN6855; USB audio offloaded through the ADSP (USB_RX/TX AFE ports).
- Odd ASUS hook: a mixer control `SMB1399 LCM DISABLE VOTE` (`lahaina.c:4252-4302` → `asus_battery_charger.c:3379`) turns the charger's low-current mode off while any mic path is open (charger noise in recordings).

## 2. Details

**Microphones (1).** Stock capture never touches the ADSP-side "MSM DMIC" of an external codec: the Bolero TX macro decimators read the DMICs directly (`TX DEC2 MUX = MSM_DMIC`, `TX DMIC MUX2 = DMIC0..3`, one channel to `TX_CDC_DMA_TX_3`), with the VA macro providing the 1.8 V mic bias from L2C (EVB:1277-1279, `va-vdd-micb-voltage 1800000`, 11.2 mA) and the DMIC clock (`qcom,tx-dmic-sample-rate = 2400000`, `lahaina-audio-overlay.dtsi:42`). Everything needed exists in our build: `CONFIG_SND_SOC_LPASS_TX_MACRO/VA_MACRO/MACRO_COMMON=m`, `q6afe` CDC-DMA DAIs (`q6dsp-lpass-ports.c:654, 664`), `q6afecc` clocks (patch 0063 already fixed the LPASS core HW vote/devote that the macros need), and the sm8350 LPI pinctrl exposes `dmic1_*`/`dmic2_*` on gpio6-9. What is missing is the DT: macro nodes at the stock addresses (`tx-macro@3220000`, `va-macro@3370000`, identical to sm8250) and the version question — the mainline drivers pick the register layout from the compatible (sm8250 → `LPASS_CODEC_VERSION_1_0`, sm8450 → 2.5, sc7280 unversioned) while lahaina reports Bolero 2.0; the VA macro reads the core ID registers at probe (`lpass-va-macro.c:1632`) so a trial with `qcom,sm8250-lpass-tx-macro`/`-va-macro` compatibles plus the sc7280-style clock set (no NPL clock on VA) is the cheapest first experiment; if the TX macro register offsets are off, mics come out silent rather than crashing the ADSP. DMIC3 (gpio12/13) is not available because those pins are the SENARY data lines, matching stock.

**CS35L45 DSP firmware (2).** The two stock wmfw files are identical (40328 B, WMFW v3, HALO, built 04 Dec 2020); the coefficient bins differ (5660 B, `client_tuning_name 0324_Asus_ROG5_SPK_MP_Thermal_Update_T025_Xmax0pt6`, features "Protect Lite, Picl, Input Enhance, Equalizer, Piano Distortion Limiter", `amplifier_gain 19`), so the tuning also carries the thermal model that stock relies on instead of a kernel thermal zone. Mainline `cs_dsp` reads wmfw v3, and `snd-soc-wm-adsp.ko` is already in our module set. Our route script comments that "full scale stays below the amplifier's 0 dB" precisely because the protection is absent; with the DSP running, stock keeps the digital volume at 0 dB (817 in the stock control scale, mixer:558,579) with `AMP PCM Gain 19dB`, and only the earpiece "handset" path lowers RCV to 673 (-18 dB) (mixer:2852-2863). The stock fast-switch txt files are ASCII parameter lists written straight into the CSPL algorithm (`cs35l45.c:59-209` in stock); they have no mainline equivalent and can be skipped (music tuning is the default in the bin). The power angle: mainline `cs35l45_runtime_suspend` returns early without a preloaded, running DSP, so today neither amp ever hibernates.

**ES928x jack (3).** The ROG5 is an outlier among SM8350 phones: the WCD938x's HPH/MBHC path is unused, so the mainline WCD938x/MBHC drivers we build do not help. The ESS part needs its own driver; the stock one is GPL and shows the sequence (3.3 V, 1 ms, 1.8 V, 5 ms, reset high, poll `CHIP_ID == 0x0b`, wait for `BOOT_FINISHED`, load `ES928X(A).ROM` over I2C, jack IRQ on TLMM14, impedance and 4-pole detection via MCU registers, ASoC jack with BTN_0..3 mapped to KEY_MEDIA/VOLUMEUP/VOLUMEDOWN/VOICECOMMAND). It is on the same SE17 bus as the amps, so the existing QUP-wrapper-2 activation path (`rog5_bt_activate`) already covers it. Note the ESS is I2S master: PRI MI2S must be configured as bit-clock consumer (`SND_SOC_DAIFMT_BC_FC`, no `set_sysclk`), and the `sm8250.c` startup switch has no PRIMARY case for that.

**Bit depth and clock (4).** `sm8250_be_hw_params_fixup` clamps every BE to 48 kHz/2ch/S16 and patch 0046 sets the SENARY IBIT to 1.536 MHz; stock runs the same link at S24_LE with 32-bit slots. The CS35L45 accepts S24_LE (`cs35l45.h:430-436`). Changing both together is a two-line change; changing only one desynchronises the port.

## 3. Checked, works the same or not needed
- SENARY MI2S as LPASS master on SD1 with LPI `i2s2` pins, amp reset/IRQ GPIOs, IRQ pull-ups, `asp-sdout-hiz-ctrl 0x3`: identical to stock (EVB:1490-1560 vs `audio.dtso`).
- The AFE port/clock IDs (SEN_MI2S_IBIT 0x10D), q6asm IOVA window and SMMU banks (0048/0049/0051), LPASS core vote (0063) and bit-clock release (0067): resolved; stock also votes `lpass_audio_hw_vote` per MI2S startup (`lahaina.c:5489`).
- Sample rate: stock speaker/earpiece are fixed 48 kHz too (`audio_policy_configuration_ZS673KS.xml:64-82`); PipeWire resampling is equivalent.
- USB-C analog audio (FSA4480), SoundWire haptics, WSA883x, WCD938x, USB-audio ADSP offload, SLIMBUS BT offload: disabled or not needed on mainline. Our config still builds WCD/WSA/SoundWire modules; harmless.
- Over-temperature/short/calibration-error IRQs: mainline handles `TEMP_ERR`, `AMP_SHORT_ERR`, `AMP_CAL_ERR` by muting (`cs35l45.c:1219-1220`), the same set stock reports (`cs35l45.c:2083-2111` stock).
- Deep-sleep interaction of audio (ADSP sleep counter): already handled by 0063/0067 and the separate CXSD agent.
