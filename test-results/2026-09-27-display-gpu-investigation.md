## 2. Evidence per display issue

### 2.1 Boot noise
- Panel patch 0037: `prepare()` (lines 380-437): regulators → 10 ms → Iris6 bypass handshake → **hardware reset** (1+1+10 ms) → 0x11 + 10 ms → 0x35 00 / 0x44 0x0980 → vendor init → 2A/2B 0..0x437/0..0x98F → 0x9D/0x9E → PPS + compression → 28 ms. `enable()` (439-457): LP mode, `0x51 00 00`, `0x53 20`, `0x55 00`, **0x29**. GRAM has never been written at that point.
- `msm_atomic_commit_tail()` (`msm_atomic.c:190-268`): `commit_modeset_enables` (panel enable inside) → `flush_commit` → kickoff at the tear-check start window → transfer (13 ms at 200 MHz). Noise window with a normal commit ≤ ~30 ms.
- UBWC: `drivers/soc/qcom/ubwc_config.c:199-208` (`sm8350_data`) consumed by both `msm_mdss.c:199-223` (`_6x_setup_ubwc`, hw rev 0x70000000) and `a6xx_gpu.c:752-800`; stock `lahaina-gpu.dtsi:50-52` (HBB 16, min-access 32, ubwc-mode 4), `display/lahaina-sde-common.dtsi:154-157` (0x400, swizzle 6). Live `dri/1/state`: plane-0 `fb=93 format=XR24 modifier=0x0`. On card1, `gbm_bo_create_with_modifiers2([QCOM_COMPRESSED])` returns a *linear* BO.

### 2.2 DSI link, timings, 120 Hz
- Live: `dsi0_pll_bit_clk` 829,042,675; byte 103,630,334; pclk 138,173,780; `disp_cc_mdss_mdp_clk` 200,000,000; vsync 19,200,000.
- Rate math (`dsi_host.c:585-613`, `636-657`): bit rate = 360·vtotal·(htotal−720) for 60 Hz DSC 8 bpp; with 0053 (HFP 557, htotal 1655, vtotal 2463) = 829.0 Mb/s = stock `qcom,mdss-dsi-panel-clockrate = <830000000>` (`dsi-panel-ams678-er2-fhd-plus-dsc-cmd.dtsi:885`).
- Stock modes: timing@0 144 Hz / @1 120 Hz / @2 90 Hz: 900 MHz; @3 60 Hz: 830 MHz; all porches 30/4/14 h, 12/2/1 v. `diff` of the 120 vs 60 on-command blocks: only `02 60 10` vs `02 60 00`; timing-switch (OSC block) same ending. DSC 48/540/8/8 and TE commands identical.
- 120 Hz in mainline: second mode with HFP 129 → htotal 1227, clock 1227·2463·120/1000 = 362,651 kHz (899.6 Mb/s); send `0x60 0x10` for that mode (drm_panel gets no mode → module param, bridge mode_set, or read the DSI host mode); TE budget halves (≈105 µs by the model; DSI at 900 Mb/s = 115 µs per slice row) → do #5 first, expect to need a larger TE window.

- EBUSY: cmd-mode `flip_done` is completed by the vblank event sent from `dpu_crtc_complete_commit()` (`dpu_crtc.c:600-605`) after `wait_flush` (`KICKOFF_TIMEOUT_MS` 84, `dpu_encoder_phys.h:27`), or immediately for a disabled CRTC (`dpu_crtc.c:1259-1262`). The 01:25:52 failure was not logged as a modeset ("Modesetting" only at 01:26:26). I could not fetch wlroots 0.20 `backend/drm/drm.c` (gitlab behind Anubis) to settle whether phoc's modesets are nonblocking.
