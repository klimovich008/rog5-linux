# Kernel 5.4.210 #20 baseline

## Core smoke suite

Result: **PASS**, zero failures.

Verified kernel, DRM card, DSI connector, panel backlight, touch, ADSP control, battery supply, charger modules, default screen blanking, USB debug networking, Plasma Mobile, power-button daemon, and native UPower. Battery reported full during the latest run.

## GPU open-cycle

Result: **FAIL**.

- Raw KGSL open #1: pass.
- Raw KGSL open #2: `ETIMEDOUT`.
- Kernel: GMU `HFI Error Received: 115 902 PwrLimitsExitIdl`.
- Kernel: CP IOMMU read-translation page fault; fault address varies between boots.
- Reproduced with ACD/BCL/IFPC disabled.
- Reproduced with rail, clock, bus, and no-nap debug forces enabled.
- Reproduced independently of Mesa command submission.

Decision: keep software rendering and treat GPU acceleration as unavailable on the vendor KGSL baseline. Use upstream DRM/MSM as the 7.x GPU path.

## Display capability

Four fixed panel profiles are exposed: 60, 90, 120, and 144. Vendor capability metadata reports no qsync, DFPS, or dynamic bit-clock support. Do not expose this as VRR.

## Live repository validation

- Host repository/artifact policy: **PASS**; five recorded images matched size and SHA-256.
- Linux 7.1.4 config fragment: **PASS**; all 110 requested enabled/disabled symbols exist.
- Device shell syntax: **PASS**.
- Live non-GPU smoke suite over SSH: **PASS**, zero failures.
- KScreen fixed modes: **PASS**; 60/90/120/144 mapped to mode IDs 4/3/2/1 and each active mode was verified.
- Power-button screen cycle: **PASS**; DPMS on restored brightness, DPMS off returned brightness to zero, and the server remained reachable.
- Final state: `server`, 60 Hz, `schedutil`, DPMS off.
- Remote runtime installer: **PASS**; repaired launchers installed with timestamped backups. The resource-heavy nested GUI was intentionally left stopped during compilation.
- Docker cross-builder: PowerShell syntax and repository policy **PASS**. Runtime execution is blocked by the host's currently unavailable WSL2/virtualization backend, not by the ARM64 build design.

The latest baseline reported about 9.9 GiB available from 11.0 GiB usable memory, with the physical KDE session and radio services running.
