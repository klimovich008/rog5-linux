# GBM descriptor/allocation preparation, 2026-09-12

Added `--gbm-fd=N` to the actual Rust GLES probe. It borrows an explicitly
supplied descriptor, duplicates it with CLOEXEC, validates a bounded DRM_VERSION
query, and creates a GBM/EGL surfaceless context. It allocates an explicit linear
ABGR8888 rendering BO, checks its returned layout and imports its exported FD
into EGL for shader rendering and readback. All 64 channels are checked. EGL
cleanup precedes BO/device/descriptor cleanup; PASS follows their return.
There is no DRM-node discovery, open, scanout request or implicit allocation
fallback. The external coordinator still owns exact-device/render-node admission.

The real `/dev/null` negative test demonstrated a correctness gap in the initial
implementation: Mesa accepted it as a GBM device, then failed at allocation.
The native backend attempted a dumb-buffer ioctl on `/dev/null`, not on a DRM
node. Merely creating a GBM device did not validate the descriptor. The repaired
probe checks DRM_VERSION and the driver name before loading GBM: `msm` in A660
mode, a sentinel in the controlled software fixture. Both real runtimes now
refuse `/dev/null` at that initial query. No phone or host DRM node was accessed.
