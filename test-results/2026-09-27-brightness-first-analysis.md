## 1. The exact path today (r124) and why only 4 levels

1. Backlight device `ae94000.dsi.0`: `max_brightness=1023`, `type=raw`, `scale=unknown`. Phosh sets it through gsd-power → logind `SetBrightness` (percent → `level = pct*1023/100`).
2. `ams678_er2_plus_dsc_bl_update_status()` (`drivers/gpu/drm/panel/panel-asus-rog5-ams678.c:391-434`, patches 0037+0043+0045+0061): forces LP mode (0043), then **quantises** `brightness = (1 + (b-1)*3/1023) << 8` (0045), i.e. it only ever sends DBV 0x000, 0x100, 0x200, 0x300 → that is the 4 visible levels (off + 3). It then calls `mipi_dsi_dcs_set_display_brightness_large()` (`drm_mipi_dsi.c:1501`), payload `{hi, lo}` → DCS long write: DI 0x39, WC 3, payload `51 hh ll` (2 data bytes after 0x51; this is the same shape stock uses — no 3-byte payload anywhere).
3. Why 0045 quantised in the first place — the 2026-09-23 trial (`test-results/2026-09-23-production-display-gpu-trial.md:139-161`, `development-lessons.md:4194`): HS long `51 03 FF` was ignored entirely; LP `51 00 FF` was black, `51 04 00` black, one-byte short write `51 FF` was full, and white-frame current was flat within each 256 block. So on the wire the **last payload byte of an LP long write is lost** and **HS DMA writes never arrive**. The panel does the sane thing with what it gets: a 1-param 0x51 sets only DBV[9:8]. The "Iris passes only the first byte" explanation in the notes was an inference; the Iris6 analog bypass does not parse bytes.
4. Root cause (confirmed by stock source, not yet by measurement): the msm DSI host never programs the **command DMA FIFO watermark register**. Stock (`techpack/display/msm/dsi/dsi_ctrl_hw_cmn.c:736-775`, `dsi_ctrl_hw_cmn_kickoff_command`) writes `DSI_DMA_FIFO_CTRL` before **every** DMA kickoff: with `CONFIG_PXLW_IRIS` `reg = 0x33` ("set DMA FIFO read watermark to 15/16 full"), without Iris `BIT(20)|BIT(16)|0x33` (watermarks disabled, `dsi_ctrl_hw_2_2.c:144-149`). Mainline `msm_dsi_host_cmd_xfer_commit()` (`dsi_host.c:2365-2376`) writes only DMA_BASE/LEN/TRIG; the register is not in `dsi.xml`. With the hardware default the FIFO drains before the fetch has delivered the whole packet, so a short DMA can go out with a pause: in LP escape mode a pause returns the lane to stop state and ends the packet (last byte lost); in HS the split packet is dropped by the panel. The Iris in bypass makes the timing tighter (Pixelworks' own comment), which is why stock needs the 15/16-full watermark specifically with the Iris. Register offset: techpack numbering is +4 vs mainline for every register (`DSI_CTRL` 0x04↔0x00, `DMA_CMD_OFFSET` 0x48↔`DMA_BASE` 0x44, `DMA_CMD_LENGTH` 0x4C↔`DMA_LEN` 0x48, `TRIG_DMA` 0x90↔0x8c, `LANE_CTRL` 0xAC↔0xa8, `CLK_CTRL` 0x11C↔0x118), so `DSI_DMA_FIFO_CTRL` 0x50 = mainline **0x4c**.
5. Consequence beyond brightness: every multi-byte LP init write has been truncated the same way — `F0 5A 5A` unlock (so the vendor settings B0/D1 "HFP", D5, EC error-flag, E4 and the OSC block ending in `60 00` were most likely never applied), `44 09 80` TE line (panel got 0x09xx, not 2432), `2A/2B` window, `EC 00 C2 C2 42`. After the fix the panel will receive its full stock init for the first time → **re-check the top-line/tear behaviour and 0072/0054 after installing 0074**, they were tuned against a half-initialised panel.

Things checked and excluded: Iris one-wire handshake (our 2 pulses × 56 µs + 237 µs = stock `IRIS_ENTER_ANALOG_BYPASS`, `dsi_iris6_gpio.c:15,223-258`, enum `dsi_iris6_gpio.h:5-16`); Iris GPIOs (ER1+ overlay: wakeup gpio92, ready gpio84 = ours; Iris reset gpio93 is `out high` from the bootloader, so not held in reset); esc clock 19.2 MHz (stock-typical); clock-lane forcing (neither stock nor mainline forces continuous clock for this panel); packet builder (`mipi_dsi_create_packet` WC and the "MSM format" header are identical to stock's `dsi_ctrl_copy_and_pad_cmd`).

## 2. How stock drives brightness

- DT (`ZS673KS-SR1-overlay.dts:88-100`, ER2 panel): `bl_ctrl_dcs`, `bl-min-level 1`, `bl-max-level 1023`, `brightness-max-level 1023`, `qcom,mdss-dsi-bl-inverted-dbv` (panel dtsi line 42). Post-on: `39 … 03 51 00 00`, `53 20`, `55 00`, `29`. HBM: `53 E0`/`53 28`.
- `dsi_panel_update_backlight()` (`dsi_panel.c:654-712`): `dsi_anakin_backlightupdate()` (`dsi_anakin.c:1200-1222`: identity except DBV 1→2, 9→10, and a DC-dimming floor of 224 only in dc/csc mode), byte-swap for inverted DBV, then in **ABYP**: `mipi_dsi_dcs_set_display_brightness()` → same wire packet `39 WC=3 51 hh ll`, **HS mode** (bl `lp_mode` false); in **PT** mode: `iris_update_backlight()` (`dsi_iris6_pq.c:2433-2480`) builds the same 3-byte `{0x51, hh, ll}` DCS long write and sends it through `iris_pt_send_panel_cmd` in HS (Iris re-emits it to the panel). No Iris OCP/"dbv" command, no 3-byte payload, no special 2-byte pass-through command — the fine brightness comes purely from an intact 10-bit DCS write.
- Stock default Iris mode is PT (`iris_lp_init`, `dsi_iris6_lp.c:110`), ABYP on request; we can only use ABYP (no Iris firmware), which is the same wire path stock uses in ABYP.

## 3. Fix

**Patch 0074 (msm):** adds `DMA_FIFO_CTRL` (0x4c, WR/RD watermark [1:0]/[5:4], disable bits 16/20) to `dsi.xml`, and in `msm_dsi_host_cmd_xfer_commit()` writes `dma_fifo_ctrl` before DMA_BASE on DSI 6G ≥ v2.2.1 (sm8350 = v2.5.0). Module parameter `dma_fifo_ctrl`: **0x33 default** (stock with Iris), `0x110033` (stock without Iris), `-1` (hardware default = today's behaviour). Per-kickoff write like stock; ~1 register write per command.

**Patch 0075 (panel):** removes the 3-level quantisation and sends the backlight value as the 10-bit DBV; keeps stock's 1→2 and 9→10 substitutions; LP stays the default, `bl_hs=1` selects stock's HS mode. **Bytes on the wire (unchanged shape):** DSI long packet, DI `0x39`, WC `0x0003`, payload `51 hh ll` (hh = DBV[9:8], ll = DBV[7:0]), hardware CRC — i.e. 0x51 followed by exactly two bytes, as stock's `39 01 00 00 00 00 03 51 hh ll`. Never three.

**Phosh/gsd side:** nothing required. `max_brightness` stays 1023; gsd-power maps percent → level linearly through logind and phosh 0.57's own `brightness-manager.c`/`auto-brightness-bucket.c` (auto-brightness from iio-sensor-proxy, `HasAmbientLight=true`, 4.2 lux read live; `ambient-enabled=true`) operate in percent, so they get 1023 steps automatically. Optional later polish: set `props.scale = BACKLIGHT_SCALE_LINEAR` (DBV is luminance-linear on this DDIC) so tools that read `scale` don't see "unknown"; the slider will feel front-heavy (linear nits), which is a phosh/gsd curve question, not a kernel one. `bl-min-level 1` in stock: DBV 1 is valid (mapped to 2), so brightness 1..1023 all light the panel.

## 4. Test plan (lead)

1. RAM trial or `rog5-dev module deliver` of **0074 alone** first (msm.ko). Expect: no change in visible behaviour except that the init sequence is now complete. Check `dmesg` for DSI errors, that the panel lights, and re-look at the top edge (TE line is now really 2432; 0072/0054 may need re-tuning — the earlier tear model was built on a truncated `0x44`).
2. Add **0075**. With the user watching: `brightnessctl`/phosh slider through 5 %, 25 %, 50 %, 75 %, 100 % — success = monotonic, smooth steps, no black below 25 %. Read-only check: `cat /sys/class/backlight/ae94000.dsi.0/actual_brightness` matches.
3. If 0075 still shows 4 levels with `dma_fifo_ctrl=0x33`, try `0x110033` (module param, reload via the module loop), then `-1` to confirm the register is the variable. Optional read-only confirmation before any of this: the live register value at `0xae9404c` while the screen is on (busybox `devmem`, if `/dev/mem` is allowed) — expected to differ from 0x33 today.
4. Once fine brightness works in LP, test `bl_hs=1` (stock's mode); if HS works, the 0043 rationale is gone and HS can become the default (avoids LP→HS transitions mid-frame).
5. Denial's earlier "3 levels" brightness quantisation in userspace, if any, becomes wrong after 0075.

Risk: low — 0074 only changes a DMA FIFO watermark to the value stock uses on this exact SoC/bridge; fallback is the module parameter or the safe-r2 bundle. Not done: the wlroots source fetch was not needed here; no phone writes were performed.
