## Preserved failures and improvements

The first ARM64 fault run failed at startup because the earlier Python-only
runtime lacked `libgcc_s.so.1`. No probe fault boundary was reached. Adding the
exact retained library fixed the fixture; a loader preflight now prevents a
missing prerequisite from cascading through the whole fault matrix.

The first direct loader check failed because `debugfs dump` created a 0644 file.
The source inode recorded 0755. Restoring that mode fixed direct loader execution;
no source image was changed. The initial signature check could not parse the
ASCII keyring as binary; explicit dearmoring resolved that preparation error.
All failed logs remain retained rather than relabeled.

Mesa downloaded in 45.396 seconds. LLVM's first transfer exceeded its 60-second
limit after about 20 MB. The subsequent preparer resumed the partial download
with a 180-second deadline and stall detection, then required the complete
archive hash and signature. It did not redownload verified packages or accept
partial bytes. Future runs can use this frozen cache.
