### 2. Details for the top items

**1. USB across suspend.** dwc3-qcom-legacy only arms the PDC `dp_hs_phy_irq/dm_hs_phy_irq/ss_phy_irq` wake IRQs (lines 342-407) and calls `dwc3_qcom_suspend(qcom, wakeup)` with `wakeup = device_may_wakeup()`, which line 817 derives solely from the `wakeup-source` DT property. Our `usb@a6f8800` node carries the PDC interrupts (`interrupts-extended = <&pdc 14/15/17>`) but not the property, so `device_may_wakeup()` is false on glue and core; `dwc3_suspend_common()` then takes the `!device_may_wakeup(dwc->dev)` branch and runs `dwc3_core_exit()` in host mode. Effect: every s2idle (the sleep policy suspends 60 s after screen-off) resets the hub tree; a hub with a card reader or NIC re-enumerates on resume, and no USB event can wake the phone. Stock's `qcom,use-pdc-interrupts` is the same mechanism. Fix is one DT line; the trade-off is that the controller (and a bus-powered hub) stays powered through suspend, so re-measure standby.

**2. WoWLAN wake path.** Two independent paths exist and neither is wired: in-band PME needs `enable_irq_wake()` on the root port's PME service IRQ, an MSI from the DesignWare MSI domain; its bottom chip has no `.irq_set_wake` and no `IRQCHIP_SKIP_SET_WAKE`, and `msi_lib_init_dev_msi_info`/pci-msi add neither, so `set_irq_wake_real()` returns -ENXIO and `pcie_pme_suspend()` falls through to `pcie_pme_disable_interrupt()`. Out-of-band WAKE# (GPIO 96, pull-up, `pcie0_wake_default`, identical pinctrl in ours) is what stock/cnss use; mainline pcie-qcom.c never requests it (only pcie-stm32.c does, with `dev_pm_set_dedicated_wake_irq`). With 0076 the link stays up and the WCN6855 will assert WAKE#/send PME, but nothing turns that into a system wakeup. The GPIO variant is what stock uses and is independent of link state.

**3. L0s.** Stock: `qcom,no-l0s-supported`, `qcom,l1ss-sleep-disable`, `qcom,l1-2-th-scale/value` (lahaina-pcie.dtsi:112-119). Mainline sm8350 shares `cfg_1_9_0` with sm8250/sm8450 and has no `no_l0s`, so `qcom_pcie_clear_aspm_l0s()` is skipped and `pci_enable_link_state_locked(PCIE_LINK_STATE_ALL)` advertises L0s; ath11k disables ASPM for FW download and restores the saved LNKCTL (multi-MSI is available — DW supports `MSI_FLAG_MULTI_PCI_MSI` — so the "leaving ASPM disabled" branch is not taken). Whether L0s misbehaves here needs `lspci -vv` (LnkCtl ASPM) and AER counters, which I could not read.

**4. L7E.** Stock powers PMR735A L7 at 2.8 V for BT (`bt-vdd-asd`) and, in the ASUS overlay since ER1, for the Wi-Fi antenna switch. Our wcn6855-pmu node lists the same rails as stock cnss except this one (S10B io, S11B dig/aon, S12B rfa2, S1C rfa1, S2E aon-mx; wifi.dtso:26-35). Radio works, so either the bootloader leaves L7E on or the switch defaults to a usable path; a rail nobody votes can be dropped by RPMh at any time.

**5/6. USB topology (verified from the ASUS overlay).** `usb0`@a600000 = side port: DP combo PHY, driven by PM8350B/ADSP over UCSI, untouched by ASUS overlays; `usb1`@a800000 = bottom port: RT1711H on `qupv3_se13_i2c` (dtbo0 `__fixups__`: `usb1` → fragments 67/101/165, `usb2_phy1` → 147/166, `qupv3_se13_i2c` → 99/158), `extcon_usb1` disabled, `adsp-usb2-switch`, USB3803 hub on the same bus (`HUB_BYPASS` 97, `HUB_RESET` 98, `HUB_CONNECT` 173, `bb_clk3`; dtbo0:11168-11186) for the AeroActive side accessory, `pcie-mux-en` gpio on `sde_dp`. Our side-port HS-PHY override translation (`sm8350-asus-rog-phone5.dts:280-296`) checks out against `phy-qcom-snps-femto-v2.c` tables: 0xe6/0x0b/0x17 → 1743/-2090, 1780/20000/40000, -4100/-31000/2600000. The bottom-port values in the table are translated the same way from fragment 166.

**7. Role switching.** The legacy glue enables the VBUS override only when `dr_mode = peripheral` at probe or via extcon; with `otg` + UCSI role switch nothing manages `UTMI_OTG_VBUS_VALID/SW_SESSVLD_SEL` per role, which is what 0055 and the `rog5-usb-reconnect` re-init compensate for. The flattened glue's `dwc3_qcom_set_role_notifier` sets/clears the override on every role change and `pre_run_stop` re-arms it for the gadget.

### 3. Works the same / not needed

- WLAN/BT enable, SW_CTRL and antenna GPIOs: tlmm 64/65/153 and 141/142/144 output-high pull-up match stock `cnss_wlan_en_active` and `wifi_ant_switch` (dtbo0:9781-9800); the ww33 overlay's "don't drive WLAN_EN low" is sound.
- Rail voltages: S2E 976 mV, S11B 1.012 V, S10B 1.8 V, S12B 1.35 V, S1C 1.9-1.952 V equal stock `qcom,vdd-wlan-*-config`.
- PCIe0 pins (PERST 94 pull-down, CLKREQ 95 `pcie0_clkreqn`, WAKE 96 pull-up), 1 lane, PHY supplies L5B/L6B, MSI (8 groups) — same. L1/L1ss enabled both sides (stock `PCIEASPM_POWER_SUPERSAVE`, ours the driver's `PCIE_LINK_STATE_ALL`). Root-port hotplug: 0073. pcie1 disabled in both (stock ER1:317).
- Wi-Fi power save (`CFG80211_DEFAULT_PS=y`), FW crash recovery (ath11k core reset vs `cnss-enable-self-recovery`), MAC from OTP/BDF, `board-2.bin` + `regulatory.db` shipped.
- BT: 4-wire UART on SE18 pins 68-71, 3.2 Mbaud, firmware `wcnhpbtfw10/wcnhpnv10`, pwrseq BT target with BT_EN/SW_CTRL/XO deps; hci_qca IBS replaces btpower. Wi-Fi-FW-load vs QUP wrapper 2 ordering already handled by `rog5_bt_activate`.
- Not applicable in mainline: USB BAM/QDSS pipes, GSI/IPA offload, `usb_audio_qmi_dev`, cnss/icnss QMI, DRV (`qcom,drv-supported`) link retention by AOP, `qcom,pm-qos-latency = <44>` (could be mimicked with a userspace PM QoS request while a USB session is active; speculative perf item).
- Charging-while-host on the side port stays with the ADSP (UCSI power/data roles, `power-role = "dual"`); no kernel-side item found, unverified on hardware.
- Stock `WCNSS_qcom_cfg.ini`, `wlan_mac.bin` and BT NVM/MAC files are not in the extracted vendor/odm payload (only init rc files), so stock country/SAR/MAC policy could not be compared.
