## 2. Details for the top items

**1. Refresh rates.** Stock 60 Hz is the 120 Hz OSC (`D1 0x2E`, `D3 0x0B`) with `0x60 0x00`; 120 Hz differs only by `0x60 0x10` and the 900 MHz link (0053 already reproduces the 830 MHz 60 Hz link with HFP 557). 90 Hz needs `D1 0x6C`, 144 Hz `D1 0x0F` + `D3 0x09`. The AOD/nolp sequences confirm `0x60` toggles between 60 and the OSC rate without re-init. Each stock timing node also carries its own Iris lightup config (`pxlw/pxlw-iris6.dtsi:118-135`) — irrelevant in analog bypass. Mainline drm_panel gets no mode in prepare/enable; the driver must pick the mode from the connector's CRTC state in `enable()` (or a module parameter for the first test). Topology: ours already selects 2 LM + 2 DSC + 1 INTF (`dpu_encoder.c:686-692`, `dsc_count >= 2`) = stock `qcom,display-topology <2 2 1>`, so the 144 Hz per-LM pixel rate is fine; the risk is the TE/DPU race documented for 0072.

**2. ESD.** Stock only checks while DPMS_ON and not suspended (`sde_connector.c:2506-2511`); `te_rechecks` = 1 normally, 5 with override. The TE irq is requested on the same gpio82 that is muxed `mdp_vsync` (`lahaina-pinctrl.dtsi:3120-3131`, pull-down 2 mA = ours), so a GPIO IRQ on a function-muxed pad is what stock does; on mainline the DPU's rd_ptr/frame-done timeouts are the equivalent signal without touching the pad. ERR_FG (gpio27) is the panel's own error flag and the cheapest first step.

**3. Iris6.** Our one-wire timing matches stock exactly: pulse 16·16·4·10/180 = 56 µs, tail 16·16·16·10/180 = 227 µs (`dsi_iris6_gpio.c:15,223-257`), ENTER_ANALOG_BYPASS = index 1 = 2 pulses (`dsi_iris6_gpio.h:5-16`); ready-poll 50 × 3 ms = stock's exit poll. GPIO numbers 92/84 match the flashed DTBO (`dtbo0.dts:10553-10561`; the source dtsi's 172 is stale). Difference: stock lights the chip up (PT, firmware over I2C `qupv3_se8_i2c` 0x26) and then enters bypass with the standby bits (`pxlw,low-power = [00 01 01]` → abyp_lp 1 → `SYS_ABP_CTRL` 0x00800000, `dsi_iris6_lp.c:417-433`), and holds reset low while the panel is off. Ours never programs the chip; its bypass power state is whatever POR/bootloader left.

**5. Bandwidth.** `dpu_core_perf` votes avg = plane fetch ×1.2, peak = `min_dram_ib` (800 MB/s) per path at every commit; nothing lowers it when the encoder enters IDLE (only `dpu_core_perf_crtc_release_bw` at CRTC disable). Stock's RSC drops the display DDR vote in idle PC. This is a screen-on-idle floor, separate from the s2idle CXSD work.

## 3. Works the same / not needed (checked)

- Panel on/off DCS content, order and delays = stock (sleep-out +10 ms, `35 00`, `44 09 80`, HFP `B0 13 D1 6B`, CASET/PASET, FD, ERR_FG set, DSC `9D 01` + 129-byte `9E` PPS, OSC block; off `EC 00 00 00 00`, `28` +20 ms, `10` +120 ms). LP/HS states match (on/post-on LP, off HS). Ours sends the PPS + compression mode before `0x29`; stock sends PPS after its enable (which includes `0x29`) — ours is the safer order.
- Reset sequence `<0 1>,<0 1>,<1 10>` = ours (active-low gpio24, 8 mA bias-disable); rails L12C 1.8 V + L13C 3.0 V HPM = stock's vddio/vdd (`ZS673KS-EVB-overlay.dts:22-45`).
- DSC: 48×540, 8 bpc/8 bpp, block prediction, 2 slices, slice_per_pkt 1, DSC 1.1; LM/DSC/INTF topology 2/2/1 both.
- TE: gpio82 `mdp_vsync` pull-down 2 mA both; tear-check vsync_count/init_val/start_pos/rd_ptr = stock; `sync_threshold_continue` 0 (0054) vs stock 4 is intentional; `hw_vsync_mode` 1 / `sync_cfg_height` 2·vtotal vs stock 0 / 0xFFF0 harmless.
- UBWC (0x400, swizzle 6, HBB 16) same table for GPU and DPU; scanout is linear anyway. VBIF QoS remap 3 3 4 4 5 5 6 6, max_bw 11.8/15.5 GB/s, min_core_ib 2.5 GB/s, min_dram_ib 800 MB/s = stock. MDSS interconnects (mdp0/mdp1 → EBI, cpu-cfg) = stock's data-bus0/1 + reg-bus.
- Idle power collapse: both 66-8 = 58 ms in command mode (`IDLE_POWERCOLLAPSE_DURATION` / `IDLE_TIMEOUT`).
- ACL `55 00`, dimming register `53 20` at enable = stock post-on. Dither: mainline only for bpc < 8, stock none for this 8-bit DSC path.
- Suspend/resume: stock powers the panel off on DPMS off exactly like our unprepare; no doze in Phosh, so LP1/LP2/AOD-high/low/nolp (`0x60 00` + `D8 A0 00` + `53 22/23`, 40/2 nit) and the stock AOD backlight state machine are not needed. `ibb`/labibb regulator modes: this panel uses `vci_no_labibb`, nothing to port.
- DC dimming (DBV floor 224 + Iris CSC/dim layer), FOD HBM/spot masker, HDR metadata (`qcom,mdss-dsi-panel-hdr-*`, peak 4200000), dynamic DSI clock, qsync, `panel-jitter`: Android/HWC features with no consumer in Phosh; the DPU dim layer has no mainline uapi.
- Already covered elsewhere: DPU core clock for command mode (0072), encoder-from-state (0070), dumb-buffer padding (0071), VT switch (0069), DSI PLL orphan WARN at probe (noted in the 2026-09-27 investigation), boot noise before the first frame (compositor-side), USB-C DP and brightness steps (other agents).
