# Denial GLES context-version repair — 2026-09-12

The probe previously requested GLES 2.0. Pinned Denial's
[`egl_context.rs`](https://github.com/denialwm/denial/blob/85b2303e2f09ae7b7b993641f90061a200f03d53/compositor/src/bin/deniald/egl_context.rs)
requires GLES 3.2 with a 3.0 fallback. A GLES 2 pixel PASS therefore did not prove
this prerequisite. The new semantic regression failed on the old implementation
before the fix, recording `REQUEST_CONTEXT 2.0` and successful drawing.

The corrected [probe](../tools/a660/rog5-gles-readback.rs) requests an ES3-capable
configuration, tries 3.2, then tries 3.0 only after context creation fails. It
queries the actual GL major/minor version before creating shaders and refuses a
version below the requested one, negative minor versions and GL query errors.
Output records the requested/actual versions and any first-attempt EGL error.
All errors still suppress PASS, and cleanup remains mandatory.

This closes a context-version gap before buffer-sharing qualification. It does
not implement DMA-BUF import/export, native fences or the full Denial rendering
path. The shader remains a deliberately small pixel test. No upstream Denial
source or phone operation changed.
