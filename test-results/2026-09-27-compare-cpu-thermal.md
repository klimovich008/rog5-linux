## 2. Details

**#1 L3 scaling.** Stock votes the L3 per CPU through the EPSS L3 vote registers; the shared node is domain 0 / cpu 0 = base + 0x90 (S/../drivers/interconnect/qcom/epss-l3.c:25-33,113-122,179). Mainline's generic `"qcom,epss-l3"` descriptor writes exactly that register (`EPSS_REG_L3_VOTE`, O/drivers/interconnect/qcom/osm-l3.c:103-109,269), so the driver already fits; only the DT is missing. Stock's core→L3 tables: little 300 MHz→300 MHz … 1900.8→1516.8; big 300→300, 787.2→614.4, 1209.6→806.4, 1497.6→998.4, 1689.6→1248, 1900.8→1344, 2188.8→1440, 2400→1516.8 MHz (S/lahaina.dtsi:3919-3945); prime floor 1516.8 MHz above 2.4 GHz (4009-4016). Two caveats: with an OPP table present `qcom-cpufreq-hw` disables fast switching (O driver:220-238), and each `opp-hz` must match a LUT row or it is dropped by the cross-validation. `OSM_L3` is a module; cpufreq-hw is built in and will defer until it loads, so put it in the initramfs. Stock bus width for L3 is 32 bytes (S:3831).

**#2 Skin thermal.** The stock policy is not in the kernel: the ASUS thermal-engine keys everything off `virtual-therm` (= pm8350_msm_therm, ADC 0x144, user_space governor, `wake-capable-sensor`, DTBO:9449-9462). NORMAL profile: 36 °C → cpu4 1766400 / cpu7 1900800 / GPU 778 MHz; 38 → 1766400/1785600/738; 39 → 1766400/1670400/738; 41 → 1670400/1555200/540; 43 → 1209600/1190400/443; 49 → 1075200/844800/379; ASUS_SHUTDOWN 58/63/65 °C (conf lines 3-9, 250-257). We have none of those inputs: `adc@3100` is empty and `adc-tm@3400` disabled in the production DTB (B:3405-3424); the 34 zones are tsens plus PMIC die alarms. Mainline supports the parts (`qcom,spmi-adc-tm5-gen2` in O/drivers/thermal/qcom/qcom-spmi-adc-tm5.c:1051; adc7 bindings present). Note the mainline binding uses `io-channels` per adc-tm child, ratiometric with `qcom,hw-settle-time-us = <200>` (stock 0xc8 = 200 µs). PM8350B channel 0x347 needs SID 3 (present, B:3299) and PMR735A 0x44a/b SID 4 (present, B:3544); pmic@5 stays disabled, which is fine (PMR735B has no thermistor). The trip ladder should map onto `cpufreq` cooling states of `cpu4`/`cpu7` (`#cooling-cells` already there, B:320,386) and the GPU (B:2301).

**#3 Capacity/EM.** Stock dynamic-power coefficients are 100/515/845; our dtso uses 105/549/590 (from sc8280xp), so the prime looks 30 % cheaper than stock believes. Without `capacity-dmips-mhz` the arch topology reports 1024 everywhere: no `asym_cpucapacity` sched domains, no misfit migration, and `sched_energy_aware` is moot. The earlier regression (quick settings 5→60 dropped frames) is the classic "small-util UI threads land on littles" problem that Android solves with uclamp/prefer-idle; with `UCLAMP_TASK_GROUP=y` in r42 a `cpu.uclamp.min` on the session slice is the mainline-equivalent test.

**Same in both (checked):** cpufreq driver/LUT/IRQs: `qcom,cpufreq-epss` with `dcvsh-irq-0/1/2` (B:4308-4318) equals stock (S:2467-2485); hardware LMh throttling on SM8350 is firmware-side in both (stock `msm_lmh_dcvs.c` present but no lahaina LMh node; no `qcom,sm8350-lmh` needed). Frequencies: recorded maxima 1.8048/2.4192/2.8416 GHz match the stock ceilings; thermal-engine's highest caps (2227200/2265600) are below them. cpuidle: CPU states 0x40000004 with stock latencies (silver 360/531/3934, gold 702/1061/4488; B:436-458 = S/lahaina-pm.dtsi:76-113); cluster states 0x41000044 / 0x4100c344 with stock D4/LLCC-off latencies (B:462-480 = S:26-46), plus OSI in ours. bwmon: both stock monitors at the same addresses/IRQs with the stock OPP ladders (B:920-1015, R/dts/qcom/sm8350-asus-rog-phone5-bwmon.dtso). LLCC: `sm8350_data` slice table (O/drivers/soc/qcom/llcc-qcom.c:2752) matches `llcc-lahaina.c:54-72` (CPUSS 3072 …). tsens CPU trips: stock kernel trips are userspace-armed placeholders (110/112 °C silver isolate/hotplug, 60/80 gold, S/lahaina-thermal.dtsi:188-352); our 90/95 °C passive → cpufreq cooling with 110 °C critical is the mainline default and adequate for junction protection. Governors: schedutil default (`CPU_FREQ_DEFAULT_GOV_SCHEDUTIL=y`), step_wise thermal, `HZ_250`, `PREEMPT`, `ARM64_AMU_EXTN=y`, `SCHED_MC/CLUSTER=y` all sensible.

**Not needed / no mainline equivalent:** WALT, core_ctl, `cpu_isolate`/`cpu_hotplug` cooling devices, QMI/CDSP cooling, `qcom,policy-engine`, SDPM, `msm_performance`, `cpufreq-hw-debug`, per-CPU `memlat` governors (covered functionally by #1/#4), stock `qoslat` (AOP DDR QoS latency vote via QMP; no mainline client).

**Ranking for "maximum performance when needed":** #1 (L3), #4 (DDR floor), #3 (capacity so big work lands on big cores), #7, #6. **For "power efficient when idle":** #3 (EAS/EM), #8 (TEO), #2 (lets the phone run cool without hard caps). #2 and #5 are the safety items to do first regardless.
