Question: does a first-enable request at the observed 1224mV setting behave
differently from the earlier 1352mV request? Equal decoded fields do not prove
an electrically unchanged or previously valid vote. Wi-Fi remains unqualified.

## Small implementation boundary

The existing readback kernel and initramfs are reused. The diagnostic DT adds
only S12 and an unbound `rog5,s12-revote-diagnostic` consumer to the native
baseline. It uses fixed1224000uV bounds, existing RET/AUTO policy and the same
fixed VPH parent. It adds no boot-on/always-on, GPIO, PHY, PCIe or radio activation.
All other baseline properties are unchanged. The real Wi-Fi PMU is absent.

The probe's query/mode/held-enable operations now require the exact cached
voltage and fresh successful S12 reads. Mode/enable changes are followed by
readback. Bit31 remains uninterpreted; unexpected other bits or field values
refuse the operation. A successful hold stays pinned even if post-readback
fails; module-init failure must not free that hold. No disable or RET restoration
path was added. No regulator-cache seeding or global kernel policy changed.

The trace verifier pairs responses with their originating active request.
Read message0x108 cannot satisfy a write0x10108 completion gate. It requires
the exact ordered before-read/write/after-read sequence and detects lost,
mismatched or duplicated transactions. Declared mode mirroring into sleep/wake
buffers remains visible; voltage/enable programming is forbidden in query/mode.

## Meaning and next boundary

S12 requests can complete on the qualified readback kernel and minimal DT.
This is not a voltage-only comparison with V10: its kernel/DT differed, and
1224mV is not Wi-Fi voltage qualification. No physical reset cause is claimed.

The retained ASUS5.4 `rpmh-regulator.c` VRM setter sends
`ceil(min_uV/1000)` after checking the caller's maximum, without imposing the
mainline8mV selector grid. It also supports a separate initial-voltage request.
Combined with the authenticated CNSS1350mV request, this identifies a concrete
API difference to investigate; it does not prove that the retained source
exactly equals the installed WW33 binary. Do not silently replace1350 with1352.

Next: qualify the exact OEM1350mV request after the now-proven initial hold,
with fresh readback and no radio until that contract is resolved. Prefer a
fixed-resource module diagnostic using the existing kernel, not global cache
seeding or an unrelated kernel rebuild. Retain the explicit hold and reset
after any temporary framework/cache inconsistency.
