## USB host devices and s2idle

With a device on the side port, suspend entry makes xhci-hcd.1 (a600000.usb)
fault ~31k times on the apps SMMU (SID 0x0, unmapped high IOVAs) and end with
`xhci-hcd xhci-hcd.1.auto: WARNING: Host System Error`. The hub disconnects on
resume and does not re-enumerate (`couldn't allocate usb_device`) until the
xHCI is rebound. Unbinding the xHCI before suspend reset the phone during
suspend entry.

Root cause: `usb30_prim_gdsc` was `PWRSTS_OFF_ON`, so genpd collapsed the
side-port controller over s2idle (0090 had already fixed the same failure for
the bottom port's `usb30_sec_gdsc`). The faults are printed during resume.
Kernel patch 0105 keeps it in retention. r184 (kernel r85): 4 suspends with
the hub attached, no Host System Error, no SMMU faults after boot, hub and card
reader stay enumerated, full trial pass including kernel health. The
stay-awake rule below is now opt-in (`ROG5_SLEEP_USB_DEVICE_BLOCKS=1`).

Interim mitigation (r183):

- `rog5-sleep-policy` stays awake while any USB device is attached
  (`usb-device`), which also fits server use.
- `/usr/lib/systemd/system-sleep/rog5-usb-sleep` rebinds a controller that
  lost its devices over a suspend; verified twice, hub and card reader back
  3 s after resume. `rtcwake -m mem` skips system-sleep hooks, so tests use
  `rtcwake -m no` plus `systemctl suspend`.

Also found: the ramdisk's `rog5-tailscaled` (USB recovery link only) retried
every 5 s while the side port is a host (221 restarts in 20 min);
`configs/systemd/rog5-tailscaled.service.d/60-slow-retry.conf` makes it 60 s.

Resources 1.10.2 is rebuilt with `packages/resources` (Adreno name, load,
clock, temperature, per-app msm fdinfo; all core types in the CPU name).
