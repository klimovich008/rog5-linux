## 2. Details for the top items

**1. UFS.** The production kernel still carries the bring-up gate. Beyond the guards listed, `ufshcd_set_active_icc_lvl` (`ufshcd.c:9584`) and `ufshcd_configure_wb` run but their WRITE_ATTR/SET_FLAG queries are refused by `ufshcd_discovery_query_allowed` (`:175-190`, only `fDeviceInit` and `bRefClkFreq` pass), so every boot logs refused housekeeping and the device sits at its power-on ICC level with no WriteBooster. Our DT node is complete for the normal path (freq-table, interconnects, resets, `B:2022-2046`) and stock adds nothing beyond the regulator list (vcc L7, vccq L9, vddp-ref-clk L9, vccq-parent S12; `D:8098-8114`), which patch 0036 and `R/tools/s12_ufs_vote` already cover. Stock's auto-hibern8 is 5 ms (`ufs-qcom.c:1853`); mainline defaults to 150 us via ahit at `O/drivers/ufs/host/ufs-qcom.c` (unguarded), fine. Expected gains: link hibern8 + device sleep at idle, WB write speed, BKOPS. Keep 0065 (real clk leak fix) and re-run the 16-suspend loop.

**2. Watchdog.** The stock wdog node has no clock and IRQ SPI 0; mainline `qcom-wdt` (`CONFIG_QCOM_WDT=m` already in r42 `.config`) matches on `qcom,kpss-wdt`, needs `sleep_clk` (32 kHz) and the bark IRQ. The hardware bite is what makes it survive kexec, unlike softdog. Verify with the observer first: if `en` is already 1, the boot chain armed it and the kernel must pet it as soon as it probes.

**3. ALS.** Ours copies the correct register setup (50 ms IT, HD on, `rog5-vcnl36866.c:73-77` equals `vcnl36866_light_hw_set_config`), so only the scale is off: 1658 is the two-PL-chip default; ROG5 is one-PL (`Makefile:8-10`). Divide by 846 (x1.96). Stock then multiplies by a per-unit gain from `/vendor/factory/lsensor_50ms.nv` (`ASH_Algo/ALSPSsensor.c:958-969`); without it stock uses the same 846.

**4/5.** Straightforward DT and small driver additions; no vendor code needed.
