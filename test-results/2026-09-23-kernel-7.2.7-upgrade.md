# Production kernel moved to stable 7.2.7 — September 23

Goal: fast, safe module iteration and a kernel base that is easy to
upgrade. 7.1.4 is end-of-life (7.1.13 was the last 7.1 release); 7.2.7 is the
current stable. The 7.2.7 production kernel booted on the phone as a RAM trial
and passed headless, display and GPU checks.

## Phone trial (RAM only, hands-free, 19:06Z)

- Boot: SSH 54.8 s after the launch, the same as 7.1.4. Stage records
  kernel-verified through switch-root all PASS. Live kmsg streaming works
  (173 lines).
- Health: battery 100 % at 29.8 °C; only `sda` is writable; 20 modules loaded.
- Display: refgen, gpucc, the SMMU reprobe, msm `separate_gpu_kms=1` and
  the packaged in-tree panel module (0043 included). Through sysfs
  brightness 1023, a white frame drew 498 mA plus 26 mA battery; black drew 298 mA.
- GPU: A660 `gpu-initialized: 1`, rbbm idle, stock zap. Same GMU
  `PREPARE_SLUMBER` ack error as on 7.1.4.

Regressions against 7.1.4, fixed for the next image (`7fbf2c32`):

- `rog5-persistent-ssh-identity` failed: sshd re-executes on HUP and missed
  the 5 s listener check on the busier boot (the listener was healthy
  afterwards). The wait is now 30 s.
- A `WARN` in the 7.2 SPMI arbiter for the always-failing reads of the SID 5
  PMIC (`pmr735b`; stock declares only a debug node there). `&pmr735b` is
  now disabled in the board DT, and its thermal zone stays described.

The two clock WARNs during DSI PHY probe and the GMU slumber error are
unchanged from 7.1.4.

## Supporting changes

- Fast module loop `rog5-dev module build|deliver`: the vmlinux build ID is
  checked and modules go into RAM only. On the 7.1.4 kernel, `qcom_battmgr`
  was edited, built in 9 s, and replaced and tested in 5 s.
- `package-production-modules.py` replaces private one-off scripts. Its
  reproduction of the booted 7.1.4 package gave 69 of 78 files
  byte-identical; the rest are rebuilt externals and in-tree panel/ath11k.
- Host tools pinned under `~/.local/state/rog5-host-tools`: ccache 4.14
  (minisign), CPython 3.12.14 (release SHA256SUMS) and dtschema 2026.6. The
  old dtschema environment died with the removed Codex runtime.
